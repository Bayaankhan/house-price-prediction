# House Price Prediction (Pakistan)

A beginner-friendly, end-to-end machine learning project that estimates a house's price in PKR from its features, with a Streamlit web app.

> **Read this first:** the results below come from a **synthetic demo dataset** (randomly generated, prices from a made-up formula). They show that the *pipeline works*. They say **nothing** about real Pakistani property prices. To get meaningful estimates, retrain on a real dataset (see [Using real data](#using-real-data)).

## Problem statement

Given a property's city, type, area, bedrooms, bathrooms, floors and age, predict its price in Pakistani rupees (PKR). This is a **regression** problem.

| | |

**Features:** `city`, `property_type`, `area_marla`, `bedrooms`, `bathrooms`, `floors`, `age_years`
**Target:** `price_pkr`

Real-data options I found while researching (licenses **must be checked by you** on each page before use):
- Kaggle "House Prices 2023 Dataset" (Zameen.com listings; Lahore, Karachi, Faisalabad, Rawalpindi, Islamabad)
- opendata.com.pk "Property Data for Pakistan" (Zameen listings from 2020, listed as Creative Commons Attribution)

None of these cover Peshawar or Mardan, and they contain **advertised asking prices, not confirmed sale prices**.

## Run it

```powershell
python -m src.make_sample_data   # 1. create the synthetic CSV (or place your own in data/raw/)
python -m src.inspect_data       # 2. inspect the data
python -m src.train              # 3. clean, train 4 models, save the best + reports
python -m src.evaluate           # 4. re-evaluate the saved model on the test split
python -m src.predict            # 5. example prediction
streamlit run app.py             # 6. open the web app
python -m pytest                 # run the tests
```

## How the pipeline avoids data leakage

1. Exact duplicates are removed **before** splitting, so one listing cannot sit in both train and test.
2. The data is split 80/20 with a fixed seed **before** anything is learned.
3. Imputation, scaling and one-hot encoding live **inside** the scikit-learn `Pipeline`, so they are fitted on training rows only.
4. The final model is chosen by **cross-validation on the training set**, not by peeking at the test set. The test set gives one honest final score.
5. Scaling is applied only for Linear Regression; tree models do not need it.

## Results (on SYNTHETIC data; generated by `python -m src.train`)

Errors are in PKR. Test set = 200 rows never used for training or model selection.

| Model | CV RMSE | Test MAE | Test RMSE | Test R² |
|---|---:|---:|---:|---:|
| Linear Regression | 9,782,189 | 5,351,604 | 8,102,186 | 0.9179 |
| Decision Tree | 6,584,330 | 3,236,342 | 5,240,615 | 0.9656 |
| **Random Forest (selected)** | **5,269,761** | 2,738,544 | 4,615,108 | 0.9733 |
| Hist Gradient Boosting | 5,696,179 | 2,345,274 | 3,879,482 | 0.9812 |

Charts: `reports/model_comparison.png`, `reports/final_model_actual_vs_predicted.png`, `reports/eda_*.png`. The full table is in `reports/model_comparison.csv`.

**How to read this:**
- Random Forest was selected because it had the lowest cross-validated RMSE. Hist Gradient Boosting scored better on this one test split, but a 200-row test set is small, so that gap may be noise, and choosing by the test set would make the test score optimistic.
- An MAE of about 2.7 million PKR means predictions are off by about 2.7 million on average.
- R² near 0.97 is high **because the synthetic prices follow a simple formula**. Real data is far noisier, so expect much lower scores.
- Decision Tree and Random Forest show much higher training R² than test R² (see `model_comparison.csv`), a sign of mild overfitting.

## Using real data

1. Download a dataset and **check its license** and that you may redistribute it. Do not commit it to GitHub unless allowed (`data/raw/` is git-ignored).
2. Record source, license, date, area unit and price meaning in `data/README.md`.
3. Make sure the CSV has the columns listed in `src/config.py` (or adapt that file). Convert area to one unit (for example marla) and document the conversion.
4. Run `python -m src.inspect_data data/raw/your_file.csv`, then `python -m src.train --data data/raw/your_file.csv`.

## Deploying for free (Streamlit Community Cloud)

1. Create a GitHub repository and push the project (`git init`, `git add .`, `git commit`, `git remote add origin ...`, `git push`).
2. Commit the trained `models/` files only if you want the hosted app to work without retraining. `models/*.joblib` is git-ignored by default; remove that line from `.gitignore` for deployment.
3. On share.streamlit.io, connect your GitHub account, choose the repository, and set the main file to `app.py`.

Check the host's current free-tier limits before relying on it. **This project has not been deployed or tested on a hosting service.**

## Limitations

- Trained on synthetic data here; the app displays a demo-mode warning.
- With real data: asking prices are not sale prices, the data is a snapshot in time, location is only city-level (no neighbourhood), and cities or ranges missing from training give unreliable estimates.
- No tuning was done beyond sensible baseline settings.
- The model cannot know condition, finishing quality, legal status, or negotiation.
- Estimates are **not** official valuations.

## Future improvements

Neighbourhood-level location, log-transformed target, hyperparameter search on a larger real dataset, prediction intervals, price-per-marla features, periodic retraining.
